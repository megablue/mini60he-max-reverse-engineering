What it does

  • Not a feature: the ground-truth record of the one stock artifact every claim is checked against — bin/MINI 60 HE MAX_V1.52.exe.
  • Phase-1 census extracted reproducibly (see Census); the 0x7E000-byte RCDATA 4000 image and the ISP protocol are decoded in phases 2–3 on their own feature pages.
  • Facts are re-derived, never trusted — see How & why before publishing any claim that traces to the binary.

How & why

bin/ is immutable (hard rule in AGENTS.md) so every documentation claim has one unchanged referent. Before publishing a claim traced to the binary, re-hash and confirm it still matches the pin — a swapped file must not be able to silently invalidate the docs:

# from the workspace root (PowerShell)
(Get-FileHash -LiteralPath 'bin\MINI 60 HE MAX_V1.52.exe' -Algorithm SHA256).Hash
(Get-Item -LiteralPath 'bin\MINI 60 HE MAX_V1.52.exe').VersionInfo.FileVersion

Census — static extraction

analysis/probe_pe.py (run 2026-10-22, pin-enforced) parses the exe as data — it never runs it — and writes deterministic artifacts to analysis/out/; census.txt is the summary. Re-run: python analysis/probe_pe.py.

  • Imports: 19 DLLs / 599 functions. Device-facing surface is only HID.DLL (HidD_Get/SetFeature, HidD_GetAttributes, HidP_GetCaps, …) and SETUPAPI enumeration — confirms the no-device-contact fence is testable from the import table alone.
  • RT_RCDATA: 10 entries, 559,080 bytes. id 4000 holds 516,096 bytes (0x7E000, entropy 1.740), head dwords 200076f8 00000205 0000021b 0000518d …, tail …5555 aaaa — the candidate firmware image; its decode is phase 2. id 4011 is a valid zip of 12 skin/UI files (out/rcdata_4011.zip).
  • Small RCDATA (UTF-16 strings): 4007 '12345678' (ISP password), 4008 '0C45', 4009 '80A1', 4010 'SN34F280', 4012 one blank byte, 4013 build time Build time:2026/01/21 10:53, 4014 '108A' (board), 4016 'SN34F280_User.hex'. 4008 + 4009 are read by the UI as the target's VID/PID, so 108A means VID 0x0C45 / PID 0x80A1. 4015 does not exist. A separate UTF-16 string names the file the tool would expect: 108ASN34F280_User.hex (in both the ASCII and UTF-16 string dumps).

Strings and signature

  • Strings: 9,654 ASCII / 1,100 UTF-16 (min 4 chars); 159 keyword hits in out/strings_sonix_isp.txt: ISP commands with report codes ("Enter ISP Mode (0x20)", "Compare ISP Password (0x02)/(0x22)", "Set Encryption Algorithm (0x03)/(0x23)", checksum messages), the SN8F-series chip list, and the UI brand EVision 幻彩 V01.
  • Authenticode: the security directory is the file overlay (offset 0x243800, size 0x31D0, ends the file exactly) → out/cert_pkcs7.bin; analysis/probe_cert.py walks it without a crypto library and writes out/cert_info.txt.
  • Signer (verified): leaf Chinese FINDER(Dongguan) Technology Co., Ltd. — C=CN, ST=广东省, serialNumber 91441900MA544M5385, Private Organization — issued by Sectigo Public Code Signing CA EV R36 under the EV code-signing policy 2.23.140.1.3; valid 2025-01-08 → 2027-01-08; SHA-1 thumbprint B2DD667C67925DD4E7F0EC5F3479F26C26CAB3F1. Seven certificates total: the four-cert Sectigo chain plus a three-cert DigiCert chain for the RFC 3161 timestamp (DigiCert SHA256 RSA4096 Timestamp Responder 2025 1). The token's own genTime is 2026-01-21 09:46:42Z, which matches RCDATA 4013's build string 2026/01/21 10:53 — the file was signed the day it was built. The TSA certificate merely starts 2025-06-04, so reading that date as the timestamp misleads.

Traps

  • The file name lies about the version. …V1.52.exe reports PE version 2.1.2.13; a reader who keys on "V1.52" is already off.
  • Blank identity strings, but not anonymous. ProductName and CompanyName are empty while LegalCopyright names Sonix outright and the About-bar string table says Version 2.1.2.7 against PE 2.1.2.13 — the app self-reports two different versions; cite both.
  • The identity splits in two, and only one half was open. The tool calls itself "SONiX USB MCU ISP Tool" (Sonix copyright, About version 2.1.2.7) with one UI string EVision 幻彩 V01 (幻彩 = RGB branding) — a rebranded SONiX tool. The firmware half closes the name question: RCDATA 4000 carries MINI60HE MAX at 0x12060 and 0x16F7E, so "Mini60 HE Max" is no longer file-name-only. Cite the hash for the exe, and Firmware image for the product string.
  • The signer is the manufacturer, not the tool's author. Authenticode names Chinese FINDER(Dongguan) Technology Co., Ltd. while the About box names SONiX — signing identity answers "who built this copy", not "who wrote the ISP tool". Do not treat the cert CN as the product vendor.
